# ESP32 Measurement Monitor

This project runs on a NodeMCU-32S / classic ESP32. It measures the connected
hardware, publishes resistance (`RP`) and capacitance (`CP`) to Arduino Cloud,
and provides Wi-Fi setup when it cannot connect to a known network.

## What you need

- A Windows PC.
- Visual Studio Code.
- The **PlatformIO IDE** extension for VS Code.
- A NodeMCU-32S or compatible classic ESP32.
- A USB **data** cable. Some USB cables provide power only and cannot upload.
- The connected AD9833 and ADS1115 hardware used by this project.
- An Arduino Cloud account and the configured Cloud Thing/device.

Windows must show the board as a COM port. If it does not, install the driver
for the board's USB-to-serial chip. Most NodeMCU-32S boards use a Silicon Labs
CP210x or CH340 chip.

## Install the development environment

1. Install [Visual Studio Code](https://code.visualstudio.com/).
2. Open VS Code and select the **Extensions** icon in the left sidebar.
3. Search for **PlatformIO IDE** and install it.
4. Restart VS Code when PlatformIO requests it.
5. Open this project folder with **File → Open Folder**.
6. Let PlatformIO finish its first-time download of the ESP32 compiler and
   libraries. This can take several minutes on the first build.

Do not place this project inside the PlatformIO installation folder. Keep it in
a normal development directory and use Git to track its changes.

## Project layout

```text
platformio.ini              PlatformIO board, framework, and library settings
src/main.cpp                Application code
include/thingProperties.h   Arduino Cloud device and variable definitions
include/arduino_secrets.h   Local Wi-Fi and device secrets; never committed
working_code.ino            Original Arduino sketch kept for reference
```

The `.pio` directory is generated by PlatformIO and is intentionally ignored by
Git. The `arduino_secrets.h` file is also ignored because it contains private
credentials.

## Configure private secrets

Create or edit `include/arduino_secrets.h` locally. It must define the Arduino
Cloud device key. Never commit this file or share its contents.

```cpp
#pragma once

#define SECRET_SSID ""
#define SECRET_PASS ""
#define SECRET_DEVICE_KEY "paste-your-Arduino-Cloud-device-key-here"
```

The Wi-Fi Manager branches do not use `SECRET_SSID` or `SECRET_PASS` for normal
operation; they remain for compatibility. The device key is required for
Arduino Cloud authentication.

## Build the firmware

In VS Code, use the PlatformIO buttons in the bottom status bar:

- **Check mark**: Build the project.
- **Right arrow**: Upload the built firmware to the ESP32.
- **Plug icon**: Open the serial monitor.

The first build downloads and compiles dependencies, so it takes longer. A
successful build ends with `SUCCESS`.

You can also build from a terminal opened in this folder:

```powershell
pio run
```

## Upload to the NodeMCU-32S

1. Connect the ESP32 using a USB data cable.
2. Confirm that Windows assigns a COM port.
3. Stop any running Serial Monitor before uploading; it otherwise holds the
   COM port open.
4. Click the PlatformIO **Upload** arrow.

If the upload cannot enter download mode, hold the board's **BOOT** button
while Upload starts. Release it when writing begins. If an upload starts but
the chip stops responding, check the USB cable, USB port, and power stability;
temporarily disconnect external modules if needed.

## Serial monitor

Open the PlatformIO Serial Monitor after uploading. This project uses
**115200 baud**. You should see voltage, phase, resistance, capacitance, Wi-Fi,
and Arduino Cloud connection messages.

The normal measurement output includes values similar to:

```text
Rp: ... Ohms
Cp: ... nF
```

## Arduino Cloud

The Arduino Cloud Thing should contain the measurement variables used by this
firmware. The current dashboard uses resistance and capacitance.

After the ESP32 joins Wi-Fi, it connects to Arduino Cloud and publishes the
measurements periodically. A dashboard's **Live** chart starts at the current
viewing session. Select **1 H**, **1 D**, or a longer range to view retained
history. Refreshing a dashboard does not erase Cloud history.

## Wi-Fi behavior and branches

The Git branches represent alternative Wi-Fi approaches:

- `main`: first verified Arduino Cloud monitoring baseline.
- `feature/wifi-manager`: WiFiManager remembers one standard ESP32 network.
- `experiment/wifi-manager-ephemeral`: opens the setup portal at every boot.
- `feature/known-networks`: stores up to five known networks in the ESP32's
  non-volatile Preferences storage, tries visible saved networks at startup,
  then opens a setup portal if none work.

On the known-networks branch, the portal is named **ESP32-Meter-Setup**. Its
password is configured in `src/main.cpp`. Connect a phone or computer to that
network, then use the portal to select and save a Wi-Fi network. On later
boots, the ESP32 scans for known networks and connects to the first available
profile.

## Adding a new known network

When no saved network is visible or can connect, the setup portal starts
automatically. Use it to add a new network. The current implementation keeps
up to five profiles. When the list is full, the first stored profile is
replaced.

For testing with a mobile hotspot, enable a 2.4 GHz hotspot. If a known home
network is still available, the ESP32 will correctly reconnect to it instead of
opening the portal. Make the known network unavailable to test portal fallback.

## Git workflow

Always confirm your branch before making a change:

```powershell
git status --branch
```

Build and test before committing. Keep `main` as the verified baseline; develop
experiments on feature branches. Do not commit `include/arduino_secrets.h`,
`.pio`, or generated VS Code configuration files.

## Troubleshooting

| Symptom | Likely fix |
| --- | --- |
| No COM port | Check the cable, reconnect the board, then install the CP210x or CH340 driver if needed. |
| Upload cannot connect | Hold BOOT while uploading begins. |
| Upload says chip stopped responding | Try another USB data cable/port and disconnect external hardware temporarily. |
| Upload says COM port is busy | Stop the Serial Monitor with `Ctrl+C`. |
| Wi-Fi connects but Cloud values are stale | Check the serial log for Cloud connection errors and verify the device key. |
| Setup portal does not appear | A saved network may be visible and working; disable it temporarily to test fallback. |
